# Pre-1.0 versioning: breaking changes ship in minor bumps

OxMPL is pre-1.0, and its core abstractions are still moving (the `State`/`AnyState` split shipped after v0.6.0; NN data structures and samplers are still ahead). With `bump-minor-pre-major: false` in `release-please-config.json`, the already-merged `feat(base)!` commit would cause release-please to propose **1.0.0** as the next release — a public API-stability commitment made as a side effect of a config default, not a decision.

We decided: set `bump-minor-pre-major: true` so breaking changes bump the minor (`0.7.0`, `0.8.0`, …), and treat 1.0 as a deliberate milestone deferred until the public API has survived feature releases on both sides of it (path simplification, NN data structures). Until then, consumers of 0.x releases must expect breaking changes between minor versions — that is the Rust pre-1.0 convention.
