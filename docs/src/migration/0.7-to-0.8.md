# Migrating from 0.7 to 0.8

0.8 is a toolchain refresh: no planner behaviour changed, but the minimum supported toolchains went up and the Rust API follows `rand` 0.10.

## Rust

### Minimum Rust version is now 1.85

All crates are on edition 2024 and declare `rust-version = "1.85"`. Older compilers fail with a clear "requires rustc 1.85" error.

### `rand` 0.10 trait rename

OxMPL's sampling traits take a random number generator, so they follow `rand`'s 0.10 rename:

| rand 0.9 | rand 0.10 | What it is |
|---|---|---|
| `RngCore` | `Rng` | The core generator (`next_u32`, `next_u64`, `fill_bytes`) |
| `Rng` | `RngExt` | The convenience methods (`random`, `random_range`, `random_bool`) |

This affects you if you implement `StateSpace`, `Goal` / `GoalSampleableRegion` or `AnyStateSpace` yourself.

**Trait bounds stay `Rng`.** The signatures are unchanged in name:

```rust
fn sample_uniform(&self, rng: &mut impl Rng) -> Result<Self::StateType, StateSamplingError>;
fn sample_goal(&self, rng: &mut impl Rng) -> Result<S, StateSamplingError>;
```

**Calling the convenience methods now needs `RngExt` in scope.** Update your `rand` dependency to `0.10` and change the import wherever you call `.random()`, `.random_range()` or `.random_bool()`:

```rust
// 0.7
use rand::Rng;

// 0.8
use rand::{Rng, RngExt};
```

If a file only names `Rng` in a signature and never calls those methods, keep `use rand::Rng;`. Importing `RngExt` there triggers an unused-import warning.

**`AnyStateSpace::sample_uniform_dyn`** now takes `&mut dyn Rng` instead of `&mut dyn RngCore`.

**Seeded runs are unaffected:** a given seed produces the same sequence on 0.8 as on 0.7.

## Python

### Python 3.11 or later is required

`oxmpl-py` 0.8 requires Python 3.11+; Python 3.8–3.10 are no longer supported. `pip` on an older interpreter resolves to the last compatible release (0.7.x) instead of installing 0.8.

The Python API itself is unchanged.

## JavaScript

No changes are needed. Building from source now requires Node.js 22.12+; using the published npm package does not.
